# 보안 경계

Harness의 정책은 플러그인 내부 작업을 통제한다. 악성 Obsidian 플러그인, 운영체제 침해, 관리자 파일 조작을 격리하는 샌드박스가 아니다.

- 노트 읽기, 모델 전송, 노트 쓰기 권한은 별개다. 자료와 요청 문자열을 어떤 모델로 보낼지 직접 지정한다.
- 공개 HTTPS/사내 endpoint도 명시한 주소만 요청한다. 리다이렉트를 따라가지 않는다. 사설망 HTTP 허용은 TLS 암호화를 제공하지 않는다. TLS 검증 비활성화 기능은 없다.
- 소스 본문/댓글/메타데이터/기억은 신뢰하지 않는 데이터로 넣으며, 소스에 도구나 정책을 변경할 권한을 부여하지 않는다. 생성된 URL/소스 ID를 그대로 실행하지 않는다.
- 비밀값은 SecretStorage에 두고 일반 설정에는 참조만 저장한다. ChatGPT OAuth는 전용 등록·PKCE·state/nonce·서명/issuer/audience 검사·권한 검사·refresh 직렬화·계정 epoch 검사를 사용한다. 기존 앱의 로그인 토큰을 가져오지 않는다.
- 본문 전체 프롬프트와 인증 헤더는 로그에 기록하지 않는다. 연결 오류는 HTTP 응답 본문을 보여주지 않는다. 원문과 임시 초안은 로컬 색인/복구 저장소에 존재하며 평문일 수 있다.
- 전송 철회 즉시 후속 요청·승인 적용을 차단한다. 읽기 철회는 검색/화면/맥락 접근을 차단한다. 운영 데이터 정리는 백업까지 새 스냅샷으로 교체하지만 OS/클라우드 백업의 삭제를 보장하지 않는다.
- 모델 출력의 문장 자체가 참인지는 자동으로 증명하지 않는다. 근거 ID/형식/버전 검증과 실제 사실 검토를 구분한다.
- 입력·출력 한도는 UTF-8 바이트 수를 기반으로 한 보수적 토큰 예산이다. Provider 보고량과 보수 추정 중 큰 출력값으로 한도를 적용한다. 정확한 청구 토큰/비용 측정이 아니며 가격은 미설정으로 표시한다.
- ChatGPT 요금제 사용 API는 `max_output_tokens`를 지원하지 않는다. 클라이언트의 응답 크기·시간·결과 예산 차단이 서버의 선제 생성/비용 상한을 보장하지 않는다.

신고/검증 시 실제 업무 노트, 키, OAuth 토큰을 GitHub issue나 로그에 첨부하지 않는다. 재현에는 합성 Vault를 사용한다. 단일 파일 쓰기 전후 장애, 승인 우회, 철회 자료 전송이 재현되면 업무 적용을 중단하고 [검증표](workplace-validation.md)에 기록한다.
