# Synthetic Search Benchmark

실제 업무 자료, 자격 증명, 외부 API, Obsidian 앱을 사용하지 않는 재현 가능한 모듈 벤치마크다. `node scripts/benchmark.mjs --label=current`로 실행한다. 5,000개 합성 Markdown 문서를 증분 upsert하여 제목당 8개 조각을 만든다. 한국어·코드 식별자·이슈 번호 질의 30개를 동일한 순서로 실행한다. 검색 방식별 2회 예열 후 실제 `SearchIndex.search`를 측정한다. 읽기·전송 정책과 최신 해시 검증 콜백도 실행한다. 영속 파일 저장 콜백은 주입하지 않는다.

하이브리드는 SHA-256에서 만든 결정적인 8차원 mock 벡터를 fixture에 공급한다. 검색 query embedding도 같은 순수 함수이다. 의미 검색 품질, 실제 임베딩 모델 지연, 네트워크, Obsidian 렌더링, 전체 앱 CPU/RSS, 색인 DB 영속 I/O 성능의 측정값이 아니다. RSS는 worker와 부모를 포함하는 Node 프로세스 값이며 heap은 worker 값이다. P95는 nearest-rank 방식이다. 기본 작업 제한은 60초이며 제한에 도달하면 완료된 표본만 표시하고 추정하지 않는다.

## baseline-before-source-map

- 상태: time-limit (hybrid warmup에서 60초 상한)
- 실행 환경: v26.10.0, darwin/arm64, Apple M6
- 합성 문서: 5,000개 / 조각: 40,000개 / 원문 UTF-8: 4,811,120 bytes
- 증분 분할·색인 구성: 2475.17 ms
- mock 벡터 fixture 구성: 850.04 ms
- 전체 worker 경과: 60000.00 ms
- RSS: 214.87 MiB / worker heap: 79.89 MiB

| 방식 | 완료 표본 | P50 (ms) | P95 (ms) | 최대 (ms) |
|---|---:|---:|---:|---:|
| 키워드 | 30/30 | 1633.21 | 1870.56 | 1935.04 |
| 하이브리드 mock | 0/30 | 미측정 | 미측정 | 미측정 |


## after-source-map

- 상태: completed
- 실행 환경: v26.10.0, darwin/arm64, Apple M6
- 합성 문서: 5,000개 / 조각: 40,000개 / 원문 UTF-8: 4,811,120 bytes
- 증분 분할·색인 구성: 2493.11 ms
- mock 벡터 fixture 구성: 39.59 ms

- RSS: 360.83 MiB / worker heap: 227.83 MiB

| 하이브리드 mock | 30/30 | 42.17 | 57.34 | 61.53 |


## 해석과 한계

같은 합성 문서와 같은 질의에서 키워드 P95는 1,870.56ms에서 47.94ms로 줄었다. 변경은 조각마다 전체 문서를 선형 탐색하던 source lookup을 현재 문서 스냅샷의 맵으로 바꾼 것이다. 비동기 원문 검증 이후에는 맵을 다시 구성하고 현재 해시·권한을 검사한다. 최적화 전 하이브리드 측정은 60초 제한으로 완료하지 못했으므로 전후 하이브리드 속도 비율은 계산하지 않는다.

최적화 후 하이브리드 mock P95는 57.34ms였고 전체 worker 실행은 5.11초였다. 데이터는 5,000개 문서·40,000개 조각이지만 원문은 약 4.81MB로, 100MB 원문 코퍼스를 검증한 결과가 아니다. RSS/heap은 마지막 보고 시점의 수치이며 최대 사용량이 아니다. 두 실행은 완료한 단계와 GC 시점이 달라 메모리 전후 비교 근거로 사용할 수 없다. 실제 업무용 PC의 Node/Electron 버전, 전체 Vault 크기, 영속 저장 I/O, 임베딩 서비스 지연, 전체 Obsidian 메모리와 검색 체감 성능은 별도 검증이 필요하다.
