# 운영과 복구

## 시험 데이터

별도 시험 Vault에 `Work/ProjectA/2026-10-15.md`를 만들고 예제 기록을 넣는다. 개인/회사 비밀 자료 대신 아래처럼 합성 기록을 사용한다.

```md
---
project: ProjectA
tags: [qa, harness]
unknown-property: preserve-me
---
# 2026-10-15
watchdog 조사: sem_timedwait 반환값 처리 누락을 확인했다.
- [ ] 회귀 시험 추가 (담당자와 마감 미정)
```

기준 날짜는 실제 시험 날짜에 맞춘다. `Daily/<시험날짜>.md`에는 관리 구역 밖 본문과 임의 frontmatter를 넣어 보존을 확인한다. 생성 모델만 연결한 일간 초안부터 시험할 수 있다. RAG 답변은 임베딩 연결·벡터 준비까지 완료해야 한다.

## 상태 저장소

설정에 표시된 위치의 `state.json`이 현재 상태, `state.json.bak`가 직전 정상 상태다. `state.lock`은 동일 기기에서 중복 writer를 막는다. 현재 살아 있는 프로세스의 잠금을 강제로 삭제하지 않는다. 프로세스가 죽은 잠금만 시작 시 보존 이름으로 옮긴다. Vault 경로가 바뀌면 별도 상태 폴더가 만들어지므로 기존 폴더는 자동 병합되지 않는다.

손상이 표시되면:

1. 플러그인을 비활성화하고 관련 Obsidian 인스턴스를 종료한다.
2. 상태 폴더 전체를 안전한 로컬 위치에 백업한다. 원문이 포함될 수 있다.
3. `state.json`과 `.bak`의 유효 JSON/스키마 버전을 확인한다. 원본 손상 파일은 별도 이름으로 보존한다.
4. 백업이 정상임을 확인한 경우에만 `.bak` 복사본을 `state.json`으로 복원한다. 이 과정은 자동으로 하지 않는다.
5. 시험 Vault에서 다시 시작한다. applying intent의 현재 파일 해시 비교 결과와 승인 대기 목록을 확인한다.
6. 검색 파생 데이터만 문제라면 정상 운영 상태로 돌아온 뒤 설정의 재구축을 사용한다. 원본 Markdown은 삭제하지 않는다.

실제로 파일에 적용됐지만 기록 직전 종료된 변경은 `expectedHash` 일치로 완료를 복구한다. 원본과 예상 결과 어느 쪽에도 일치하지 않으면 수동 확인을 요청한다. 같은 변경을 무조건 재적용하지 않는다.

## 갱신과 제거

업데이트 전에 플러그인을 끄고 `main.js`, `manifest.json`, `styles.css` 세 파일만 교체한다. `data.json`에 토큰을 복사하지 않는다. 제거 시 플러그인 폴더 삭제만으로 Vault 밖 상태나 SecretStorage 인증이 삭제되지는 않는다. 먼저 ChatGPT 로그아웃/모델 전송 철회와 운영 데이터 보존 필요 여부를 확인한다. 자동으로 개인 노트를 지우지 않는다.

## 사내 TLS/프록시

사내 CA와 프록시를 운영체제/Obsidian 런타임이 신뢰하도록 회사 IT 정책에 맞춰 구성한다. 이 MVP에는 사용자 지정 CA, 프록시 설정 UI, 인증서 검증 우회가 없다. 실제 사내 서버 연결은 배포 대상 PC에서 검증해야 한다.
