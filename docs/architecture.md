# 구현 구조와 결정

Obsidian 진입점이 모듈을 조립하는 단일 데스크톱 플러그인이다. 별도 서버나 daemon을 요구하지 않는다. 패널/설정 → Runtime → 정책·예산·검색·모델 → 검증된 ChangeSet → 명시적 승인 → Vault Adapter 순서다.

## 고정 Workflow

일간 정리는 허용 범위와 모델을 확인하고, 선택 GitHub를 동기화한 뒤 최근 기록에서 최대 8개 조각(문서당 최대 3개)을 선택한다. 모델에 정책 결정을 위임하지 않는다. 기억/본문은 JSON 데이터이며 Skill만 사용자가 활성화한 지침이다. 생성 결과를 엄격한 스키마와 근거 ID로 검사하고, 실패 시 1회만 교정한다. JSON Schema 지원 없는 모델도 텍스트 출력 후 같은 검증을 받는다. 임의 Tool/함수/셸은 모델에 노출하지 않는다.

조회 대상의 수정일은 사건 발생일이 아니다. 모델 지침과 화면에서 이 차이를 명시한다. 근거 연결과 JSON 검증은 실제 주장에 대한 의미적 사실 검증을 대체하지 않으며 최종 초안 검토는 사용자가 수행한다.

## 정책

초기 읽기/쓰기/전송 배열은 비어 있다. Vault 상대 경로의 하위 트리만 허용한다. `.`은 명시적인 전체 Vault 범위이며 기본값이 아니다. 시스템/운영/제외 폴더는 읽기 금지다. 경로 정규화와 각 구성요소의 symlink 검사를 함께 수행한다.

전송 대상은 목적(generation/embedding), provider 종류, 정규화된 주소, 모델 ID의 조합이다. 생성과 임베딩은 독립적인 승인을 요구한다. 원문 자료의 허용 범위는 기억과 생성물의 근거에도 상속된다. 정책 변경은 실행 취소와 버전 증가, 파생 자료 무효화를 발생시킨다.

## 쓰기와 복구

ChangeSet은 대상 원문, 예상 결과, 변경 내용, 근거 버전, 정책 버전, 만료를 해시에 포함한다. 열린 Markdown 편집기가 있으면 저장 여부 추측 없이 적용을 막는다. 닫힌 파일은 `Vault.process` 동기 콜백 안에서 최신 해시를 비교한다. 신규 파일 생성은 기존 경로를 덮어쓰지 않는다.

운영 상태에 적용 의도를 먼저 저장한 뒤 파일을 바꾸고 실제 해시를 확인한다. 재시작 시 예상 결과와 같으면 완료로 복구하고, 기준 원문과 같으면 재승인을 기다리며, 둘 다 아니면 차단한다. 무조건 재실행하지 않는다. 역변경도 현재 버전 일치와 별도 승인이 필요하다. 신규 파일을 삭제하는 역변경은 제공하지 않는다.

## 로컬 저장 결정

네이티브 DB 배포 의존성을 줄이기 위해 JSON 스냅샷 + 파일 잠금 + 임시 파일 fsync/rename + 직전 정상 백업을 사용한다. 스키마 버전은 1이며 모르는 버전/손상은 읽기 전용이다. 원문과 DB 간 원자성을 주장하지 않는다. 검색의 체크포인트는 같은 상태 파일에 유지한다.

이 선택은 개인 시험용 MVP를 위한 것이다. 대형 Vault에서는 전체 스냅샷 저장과 앱 파일 스캔 비용을 따로 측정해야 한다. Search 벤치마크만으로 Obsidian 이벤트 반영 지연·UI 메모리·실제 디스크 저장 p95를 충족했다고 주장하지 않는다. SQLite/worker/분할 저장은 그 측정 결과에 따라 후속 도입할 수 있다.

## 확장 제한

사용자 Skill은 Markdown + strict manifest이며 MVP의 일간 입출력 계약을 따른다. 실행 시 파일 해시를 다시 검사하고 활성화 때 검토한 버전만 사용한다. 새 Workflow/임의 코드/설치 명령은 지원하지 않는다. GitHub 쓰기, MCP, 캘린더, 상주 Runner, 모바일은 미포함이다.
